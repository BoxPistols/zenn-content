## これは何か

[Hachibu](https://github.com/BoxPistols/hachibu)は、Claude Codeのモデル、effort、使用率を、Macの画面の最前面に常駐する小さなバーに出すmacOSアプリです。MITライセンスで公開しています。Anthropicとは関係のない、個人が作った非公式のツールです。

![バーの表示](https://raw.githubusercontent.com/BoxPistols/hachibu/main/docs/images/strip-basic.png)

`Opus5• xhigh · S42 W76 F93`は、モデル、effort、5時間枠、週枠、モデル別の週枠の順です。モデル名の後ろの点は1Mコンテキストを表します。使用率は70%で黄、90%で赤の札になり、閾値は変えられます。

![マウスを乗せると広がり、右クリックでモードを切り替える](https://raw.githubusercontent.com/BoxPistols/hachibu/main/docs/images/demo.gif)

人生のけっこうな時間を、トークンの残量確認に使っていました。名前は「腹八分」から取っています。

## 作った経緯

Touch Bar付きのMacBookでは、BetterTouchToolと自作のスクリプトでClaude Codeの使用率をTouch Barに出していました。`/usage`を打たなくても残量が視界に入る状態は快適でしたが、Touch Barの無いMacでは再現できません。そこで、画面側に常駐する単体のアプリにしました。

先に既存のツールを調べました。ccusageやCodexBarをはじめ、Claude Codeの使用率を出すツールは多数あります。大半はメニューバーの項目か、ターミナルの中で動くものです。メニューバーは、開かないと数字が見えないか、常に幅を取るかのどちらかになります。Hachibuは次の点を目的にしました。

- 開かなくても見える。フルスクリーンのアプリの上にも出る
- 作業の邪魔をしない。押してもフォーカスを奪わず、使用率だけ、端に収納、隠す、の表示を選べる
- ほかの道具に頼らず、入れるだけで動く

公式のClaudeデスクトップアプリも、メニューバーの項目から使用率を見られます。そちらはクリックして開く形なので、常時表示という点で役割が分かれます。

## Xcodeなしで作る

開発はSwift 6＋SwiftPMで、Xcodeは入れていません。Command Line Toolsだけで、ビルド、テスト、.appの組み立て、Universal Binary化までできます。いくつか、Xcodeがあれば出会わない問題がありました。

### @Stateが使えない

Command Line Toolsの構成では、SwiftUIの`@State`を展開するマクロのプラグインが見つからず、ビルドが通りませんでした。ビューの状態は`ObservableObject`の`@Published`に持たせています。ビューが値を持たない形になるので、後述の画面外への書き出しとも相性が良くなりました。

### XCTestが無い

XCTestはXcodeに同梱されているため使えません。Swift Testingは使えますが、こちらもマクロのプラグインの場所を明示する必要がありました。

```sh
swift build --build-tests \
  -Xswiftc -plugin-path \
  -Xswiftc "$(xcode-select -p)/usr/lib/swift/host/plugins/testing"
swift test --skip-build
```

### .appは手で組み立てる

`swift build`が作るのは実行ファイルだけです。`Contents/MacOS`に実行ファイル、`Contents/Resources`にアイコン、`Info.plist`を置き、`codesign --sign -`でアドホック署名をすれば.appになります。`--arch arm64 --arch x86_64`を付ければ、Apple SiliconとIntelの両方で動くバイナリになります。アイコンもSwiftのスクリプトでCoreGraphicsから描き、`iconutil`で.icnsにしています。

## フォーカスを奪わないバー

バーは`NSPanel`に`.nonactivatingPanel`を指定し、`canBecomeKey`を`false`にしています。押しても前面のアプリが入れ替わらず、入力中の文字が途切れません。

この構成では、いくつかの既定の挙動が合いませんでした。

- 窓の背景をドラッグで動かせる設定にしていると、SwiftUIのボタンが押下をドラッグの開始として取られます。ホスティングビューとぼかしのビューの両方で`mouseDownCanMoveWindow`を`false`にし、移動はつまみの部分だけで`performDrag`を呼ぶようにしました
- アプリが非アクティブの間は、コードから開くメニュー（`NSMenu.popUp`）が出ません。右クリックメニューは`menu(for:)`で返す形にしました
- 最初のクリックが窓のアクティブ化に使われないよう、`acceptsFirstMouse`を`true`にしています

## ショートカットは「届くこと」を確かめてから保存する

バーを呼び出すグローバルショートカットは、Carbonの`RegisterEventHotKey`で登録します。登録に成功しても、押したときに届くとは限りません。macOSのショートカット（Spotlight、入力ソースの切り替えなど）はシステムが先に受け取るためです。

そこで登録の窓は3段階にしました。

1. 組み合わせを押す。macOSに割り当て済みの組み合わせ（`com.apple.symbolichotkeys`から読む）と、他のアプリが登録済みの組み合わせは、この時点で弾く
2. もう一度押してもらう。登録したショートカットとして届いたら、「保存」を押せるようになる
3. 「保存」で確定する。キャンセルは、どの段階でも窓を開く前の組み合わせに戻す

最初の実装では、試しに登録した時点で設定を書き換えていたため、「Bを試す→予約済みのCが弾かれる→キャンセル」でBが残る不具合がありました。「試す」と「保存する」を分け、状態の判断を画面から切り離してテストできる形にして直しました。

## 使用率をどこから取るか

値の出どころは2つあり、利用者が選びます。

1つはClaude CodeのstatusLineです。statusLineに指定したコマンドには、モデル名、effort、5時間枠と週枠の使用率を含むJSONが渡されます。これをファイルに保存する小さなスクリプトを挟み、アプリが読みます。公式の仕組みですが、ターミナルでClaude Codeを使っている間しか更新されず、モデル別の枠は含まれません。

もう1つは、Claude Code自身が使っている使用率のエンドポイントです。Claude Codeがキーチェーンに保存したログイン情報を使えば、モデル別の枠を含む値を、ターミナルを開いていないときも取得できます。ただし、[Claude Codeの規約](https://code.claude.com/docs/en/legal-and-compliance)はOAuthによるログインを「ordinary use of Claude Code and other native Anthropic applications」のためのものとし、開発者は「may not collect, store, or intermediate Claude.ai credentials or session tokens」としています。読み取り専用であっても、第三者のアプリがこの情報を使うことは、この文面の対象外とは言えません。

Hachibuでは、この機能を既定で無効にしています。初回の起動時に、何を使うのか、規約の文面、影響が利用者のアカウントに及ぶことを示し、利用者が有効にした場合だけ呼びます。無効にすると、キーチェーンの読み取りと通信をその場でやめ、取得済みの値も捨てます。Claude Codeの周辺ツールを作る方は、公開の前にこの規約の節を読むことをおすすめします。

## 公開の前後で起きたこと

### 作者の環境に頼った版を公開した

最初の版には、スラッシュコマンドを送るボタンや、許可の確認に応答するボタンがありました。これらは手元のBetterTouchTool用のスクリプトを呼んでおり、公開した後で、ほかの環境では動かないことに気づきました。配布物を、自分の環境に頼らない状態で一から入れて試す、という確認をしていませんでした。

機能は使用率の表示だけに絞りました。以後は、公開の前に、配布用のzipをダウンロードしたときと同じ状態（隔離属性付き）で展開し、署名、Gatekeeperの判定、空の設定での起動までを確かめています。

### 名前を2回変えた

最初の名前は、公開の前に同名のmacOSアプリが見つかって変えました。2つ目の名前Slashstripは、スラッシュコマンドのボタンに由来していましたが、そのボタンを外したので中身を表さなくなり、「strip」の連想も気になりました。

3つ目を決めるときに候補を調べたところ、Headroom、Margin、Perch、Burnbar、Tokenmeter、Quotabarなど、限度やメーターを表す英単語は、ほぼすべてClaude向けの使用率ツールが既に使っていました。日本語由来の「腹八分」にしたのは、消費の節度という意味が合うことに加えて、重なりが見つからなかったためです。

### メニューバーに項目が出ない

開発中に、メニューバーの項目だけが出なくなりました。macOS 26の「システム設定」＞「メニューバー」には、アプリごとに表示を許可するスイッチがあります。調べると、Hachibuの項目はiTermのスイッチに連動していました。

原因は、試験のために、本番のbundle idの実行ファイルをターミナルの中から直接実行していたことでした。macOSは、その項目をbundle idごとに「ターミナルのもの」として覚えます。一度紐づくと、Finderから開き直しても戻りません。記録は保護された領域にあり、消す手段も見つかりませんでした。bundle idを変え、インストールのスクリプトは`launchctl submit`経由で`open`する形にして解決しました。

ここから得た規則は2つです。

- 本番のbundle idの実行ファイルを、ターミナルから直接実行しない。試験は別のidを付けた複製で行う
- メニューバーの項目は、利用者が隠せる。すべての操作に、バーの右クリックメニューからも届くようにする。隠されているときは、設定を開く項目をメニューに出す

### 画面に出さずに見た目を確かめる

GUIの確認で窓を出したりカーソルを動かしたりすると、その間、ほかの作業が止まります。そこで、環境変数を付けて起動すると、窓を表示せずに各画面をPNGへ書き出して終わるモードを足しました。`NSHostingView`を画面外の窓に載せ、`cacheDisplay(in:to:)`で2倍の解像度のビットマップに描いています。

英語と日本語、表示モードごとのバー、同意画面、ショートカットの窓の4段階が、数秒で画像になります。READMEの画像の大半も、ここから作っています。背景のぼかしは描かれないので、実際の画面が要るのは右クリックメニューの画像とデモ動画だけになりました。

## 見た目の規則

小さい部品なので、決める数を減らしました。

- 角丸は2段。面（バー）は8、面の中の札は3。メニューバーの札も同じ3
- 色は3つ。黄と赤は使用率の段階だけに使う。1Mの点は、どちらとも見分けられる橙
- 文字は12pt未満を使わない。1Mを小さい文字にする案はこの規則に当たるので、点にして、意味はメニューの「表示の読み方」とツールチップに文字で書いた

メニューバーの文字に角丸の札を付けるには、`NSAttributedString`の背景色では足りません（角を丸められません）。絵と文字を1枚の`NSImage`に描いています。描画のブロックの中で`NSColor.labelColor`を使うと、描く時点のメニューバーの明暗に合った色になります。

## 配布について

Developer IDでの署名と公証はまだ受けていません。ダウンロードした利用者は、初回に「システム設定」＞「プライバシーとセキュリティ」で「このまま開く」を押す必要があります。READMEには、この手順を画面の画像付きで書きました。許可する前に確かめる方法として、ソースからのビルド、SHA-256の照合、アプリが読むものと送るものの一覧も載せています。

署名と公証、Homebrew cask、Mac App Storeでの配布は、issueに積んであります。App StoreはSandboxが必須で、キーチェーンの項目を読めないため、任意の使用率APIは提供できなくなります。
